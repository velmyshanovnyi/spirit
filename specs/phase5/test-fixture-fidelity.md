# Тестова фікстура = реальний index.html (backlog A7)

## Проблема

`app.test.js` тримає ~570 рядків рукописної HTML-фікстури, що мовчки
розходиться з `client/index.html` (виміряно: 2 тест-only id, 5 реальних id
відсутні у фікстурі, включно з цілою карткою notifications). Наслідок уже
траплявся двічі (A2/A3): тести їздять через `#btn-generate`, якого в проді
немає, і не бачать різниці між програмною навігацією та реальним кліком.

## Рішення

1. **Генерація**: фікстура будується з `../index.html?raw` (нативний
   vite/vitest raw-import) — витягується вміст `<body>`, вирізаються
   `<script>`-теги. Дрейф стає неможливим: будь-який елемент, доданий у
   прод-HTML, автоматично в тестах, і навпаки.
2. **Тест-only блок**: `#btn-generate` (задокументована легасі-фікстура для
   ~100 тестів) додається окремим явним `TEST_ONLY_MARKUP` із коментарем-
   виправданням — видимий борг замість невидимого.
3. `id="account-heading"` додається в реальний `index.html` (тести пінять
   переклади через нього; шкоди проду нуль, синхронізація чесніша, ніж
   тест-only дубль цілої секції).
4. **Real-trigger тест** (прямо з опису A7): клік по справжньому
   `.nav-item[data-route]` у заблокованому режимі відкриває модалку пароля —
   реальний тригер фічі A2, який рукописна фікстура ніколи не покривала.
