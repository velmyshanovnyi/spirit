# Контекст

`MULTI-AGENT.md` v6 — проєктно-незалежний нормативний протокол для кількох
автономних агентів в одному репозиторії. Складений попередньою сесією як синтез
v2–v5 і чотирьох git-експериментів (T1–T4); запис тоді впав на `ENAMETOOLONG`
(heredoc завеликий для spawn), тіло відновлено з транскрипта.

Критерії приймання, задані рев'юеру: (1) ядро L0 виконуване лише з git;
(2) внутрішня консистентність ролей/воріт/станів/СТОП/антипатернів; (3) усі
твердження про поведінку git правильні; (4) проєктна незалежність; (5) відтворюваність
без питань до людини; (6) вибіркова звірка ≥5 цитувань §14 проти v2–v5.

Рев'юер прочитав файл повністю, звірив 19/19 цитувань і **сам провів 4 git-експерименти**
в bare-репозиторії. Усі 16 знахідок мали обов'язкову структуру (шлях, рядок, цитата
≤15 слів, опис, сценарій відмови); я звірив кожну цитату з файлом — усі збігаються.

# Нові експерименти (ця ітерація)

Bare-репозиторій, два клони, Git for Windows:

- **T5** — два агенти одночасно створюють `task/TASK-001` з різними claim-комітами
  (handoff-файл з OWNER/CLAIMED_AT) через detached worktree від `origin/main`:
  `agent-a push exit=0`, `agent-b push exit=1`; сервер вказує на коміт a; локальний
  `main` у a, b і origin однаковий (seed).
- **T6** — після просування `origin/main` push приватної task-гілки зі старої бази:
  `exit 0`; `git merge-base --is-ancestor origin/main HEAD` → `exit 1` (застарілість виявлена).
- **T7** — `git ls-remote origin 'refs/heads/task/*'` показує claim з іншого клона без fetch.

# Що рев'юер підтвердив як коректне

Гонка claim-ref і семантика `--force` (§5.2); `PROTOCOL RECORD` vs `ENFORCEMENT
POINT`; форми `git diff origin/main...HEAD`, `--check`, `--ignored`; 19/19 цитувань
§14; формат знахідки/дисмісу/не-переподняття (§7.1–7.3); шлях і фронтматер артефакту
(§7.5) узгоджені з §10; умови незалежності субагента (§8.2) узгоджені з 6.10; усі 14
перехресних посилань §11; §13 не переоцінює гарантії; проєктна незалежність (крім #14).
