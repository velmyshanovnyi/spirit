# Spirit

Децентралізоване, ефемерне P2P-з'єднання (чат, дзвінки, передача файлів) у браузері — без облікового запису, без постійної серверної інфраструктури, без бази даних.

**Важливо про "анонімність":** Spirit не приховує вашу IP-адресу від співрозмовника за замовчуванням — WebRTC (пряме P2P-з'єднання, на якому Spirit побудований) структурно розкриває публічну IP-адресу обох сторін одна одній через ICE-кандидати, це властивість самого протоколу, а не недогляд коду. Приховати IP можна, лише форсувавши весь трафік через TURN-релей (потребує власного чи стороннього TURN-сервера — див. секцію "Форсувати TURN-релей" у налаштуваннях сервера). Без цього єдина гарантія — те, що *сигнальний* сервер (координація з'єднання) ніколи не бачить вміст переписки, лише службові дані для встановлення з'єднання.

## Філософія

- **Без облікового запису** — акаунт це виключно локальна пара криптографічних ключів у пам'яті браузера. Без email, телефону, OAuth за замовчуванням; OAuth (Google/Yandex/Telegram/FB) доступний як опційний шар верифікації поверх ключа, не заміна ([oauth-verification.md](docs/oauth-verification.md)).
- **Ефемерність та мультиакаунтність** — постійні зашифровані профілі або одноразові "світи", що зникають безслідно після закриття вкладки.
- **Zero-database бекенд** — сигналінг координує встановлення з'єднання через легкий PHP-скрипт із файловим сховищем, що самоочищається. Ніякі повідомлення через сервер не проходять.
- **Селективна інфраструктура** — користувач сам обирає сигнальний та STUN/TURN сервер.
- **E2EE за замовчуванням** — весь трафік у WebRTC DataChannel додатково шифрується end-to-end, сигнальний сервер бачить лише публічні ключі та SDP/ICE, ніколи вміст переписки.
