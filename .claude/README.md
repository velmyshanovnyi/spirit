# `.claude/` — конфігурація Claude Code, що їде з репозиторієм

Усе, що тут лежить, є **частиною проєкту**, а не налаштуванням конкретної людини
чи машини. Мета — щоб будь-який волонтерський Claude-акаунт після `git clone`
отримав ту саму робочу конфігурацію, без ручного донастроювання профілю.

**Проєктне має пріоритет над однойменним глобальним** (`~/.claude/...`).

## Що куди класти

| Тека / файл | Призначення | В git? |
|---|---|---|
| `agents/<name>.md` | описи субагентів проєкту | так |
| `commands/<name>.md` | слеш-команди проєкту | так |
| `skills/<name>/SKILL.md` | скіли проєкту | так |
| `settings.json` | спільні налаштування: permissions, hooks, спільні env | так |
| `launch.json` | конфіг локального дев-сервера для браузер-превʼю | так |
| `settings.local.json` | ключі, токени, локальні абсолютні шляхи | **ні** (`.gitignore`) |
| `worktrees/`, `scheduled_tasks.lock` | машинні артефакти сесій | **ні** (`.gitignore`) |

`settings.local.json` **перекриває** `settings.json` при збігу ключів — тримай
там усе, що специфічне для твоєї машини або акаунта.

## Правила

- **Жодних абсолютних шляхів під конкретну машину** (`C:\Users\<хтось>\...`) у
  файлах цієї теки — на іншій машині вони зламаються. Тільки відносні від кореня репо.
- `.gitkeep` у порожніх теках обовʼязковий — git не зберігає порожні теки.
- Глобальні агенти/скіли з профілю **копіюються** сюди, а не переміщуються:
  вони можуть використовуватись іншими проєктами на тій машині.
- Не класти сюди секрети. Секрети проєкту — `deploy/*.local.netrc` і
  `server/config.secrets.php`, обидва в `.gitignore`, обидва передаються поза git.

Процедура перенесення стану з профілю в репо — [`docs/claude-state-migration.md`](../docs/claude-state-migration.md).
